# Day 26 — Virtual Environments and Dependencies

**Status:** Full study pack. Re-create the environment and run tests before marking mastery.

## 1. Definition
A **virtual environment** is an isolated Python environment for a project. `venv` creates one; `pip` installs packages; a dependency list documents what the application needs.

## 2. Why / where / when
Use one environment per project to prevent dependency conflicts and make setup reproducible. Do not commit the environment folder itself. Keep dependency specifications in version control and document the Python version and commands required to run tests.

## 3. Syntax and workflow
Windows PowerShell:
```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install requests
python -m pip freeze > requirements.txt
python -m pip install -r requirements.txt
deactivate
```
macOS/Linux activation: `source .venv/bin/activate`. A venv isolates installed Python packages; it does not install a different Python interpreter automatically.

## 4. Five worked examples
### Example 1 — Check Python version
```python
import sys
print(sys.version_info.major, sys.version_info.minor)
```
Output depends on installed Python; use this to verify the runtime.

### Example 2 — Inspect interpreter
```python
import sys
print(sys.executable)
```
Output is the path to the current Python executable. It should point inside .venv when activated.

### Example 3 — Check installed package
```python
from importlib.metadata import version, PackageNotFoundError
try: print(version("pip"))
except PackageNotFoundError: print("Package not installed")
```
Output displays pip's installed version or a fallback.

### Example 4 — Read a dependency file as text
```from pathlib import Path
requirements = Path("requirements.txt")
print(requirements.read_text() if requirements.exists() else "No dependency file")
```
Output depends on the project file. This program checks before reading.

### Example 5 — Environment variable
```import os
mode = os.getenv("APP_MODE", "development")
print(mode)
```
Output: `development` unless APP_MODE is set. Secrets should not be committed to source.

## 5. Five tasks with solutions
### Task 1 — Report runtime
```import sys
print(f"Python {sys.version_info.major}.{sys.version_info.minor}")
```
Displays the active interpreter version.

### Task 2 — Check a package
```from importlib.metadata import version, PackageNotFoundError
try: print(version("pip"))
except PackageNotFoundError: print("Install the package in this environment")
```
Gives a clear message if not installed.

### Task 3 — Create a requirements file
Run `python -m pip freeze > requirements.txt` after installing the intended project dependencies. Verify the file contents before committing.

### Task 4 — Recreate the environment
Run `py -m venv .venv`, activate it, and run `python -m pip install -r requirements.txt`. These commands rebuild project packages in isolation.

### Task 5 — Ignore the environment folder
Add this to `.gitignore`:
```text
.venv/
__pycache__/
*.py[cod]
```
This keeps local environment and generated bytecode out of Git.

## 6. Common mistakes
- Installing a package outside the activated venv.
- Using bare pip from a different Python; prefer `python -m pip`.
- Committing .venv or secrets.
- Leaving requirements unspecific when reproducibility matters.
- Assuming venv selects the system Python version; specify the desired interpreter.

## 7. Interview Q&A
1. Why venv? **Isolates a project's Python packages.**
2. Why `python -m pip`? **Ensures pip is associated with that interpreter.**
3. Should .venv be committed? **Usually no.**
4. What is requirements.txt? **A text specification of dependencies and versions.**
5. Does a venv install Python? **No, it uses an available base interpreter.**

## 8. Project — Reproducible Starter App
Create `app.py`:
```import sys
from importlib.metadata import PackageNotFoundError, version

def runtime_report():
    try: pip_version = version("pip")
    except PackageNotFoundError: pip_version = "missing"
    return {"python": sys.version.split()[0], "pip": pip_version}

if __name__ == "__main__":
    for key, value in runtime_report().items(): print(f"{key}: {value}")
```
Create `.gitignore` with the entries above and an optional `requirements.txt` only for real external dependencies. Run `python app.py` inside the activated venv.

### Tests — `test_app.py`
```python
import unittest
from app import runtime_report

class RuntimeTests(unittest.TestCase):
    def test_has_python(self): self.assertIn("python", runtime_report())
    def test_version_nonempty(self): self.assertTrue(runtime_report()["python"])
    def test_pip_field(self): self.assertIn("pip", runtime_report())
    def test_report_is_dict(self): self.assertIsInstance(runtime_report(), dict)
    def test_keys(self): self.assertEqual(set(runtime_report()), {"python","pip"})

if __name__ == "__main__": unittest.main()
```
Run `python -m unittest -v`. No third-party dependency is needed.

## Real-world use cases — where, when and how
1. **Portfolio project:** Where: GitHub repositories. When recruiter or teammate clones the project. How: provide a requirements file and clear environment setup steps.
2. **Conflicting libraries:** Where: two Python projects needing different package versions. When dependency versions clash. How: create a separate venv for each project.
3. **Test isolation:** Where: CI pipelines. When tests should run consistently. How: create a clean environment and install declared dependencies.
4. **Deployment preparation:** Where: staging/server setup. When a new instance is configured. How: install only the application's documented dependencies.
5. **Team onboarding:** Where: shared projects. When a developer joins. How: document Python version, environment creation, install, run and test commands.
