# Python Exceptions Track

**Track purpose:** Learn error handling separately from core syntax, then apply it in projects. This is not the Data Analyst syllabus.

## Learning order
1. [Day 19 — Input Validation](../days/DAY-19-Input-Validation.md): parsing and boundary validation.
2. [Day 20 — Debugging Fundamentals](../days/DAY-20-Debugging-Fundamentals.md): tracebacks and root causes.
3. [Day 21 — Exceptions](../days/DAY-21-Exceptions.md): try/except/else/finally, raise, custom exceptions.
4. [Day 22 — Testing](../days/DAY-22-Testing.md): assertRaises, failure cases and regression tests.
5. [Day 23 — Files](../days/DAY-23-Files.md): file errors and safe persistence.

## Track completion criteria
- Handle expected errors specifically.
- Preserve the original error cause when re-raising.
- Never silently ignore errors without a documented reason.
- Test normal, boundary, malformed and missing-resource cases.
- Explain the difference between parsing errors, validation errors and programming defects.
