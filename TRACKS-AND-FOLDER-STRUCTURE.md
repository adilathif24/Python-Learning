# Repository structure

Study order: Python Core day-wise lessons; Exceptions; Files and CSV/JSON; Modules and Packages; OOP; Testing and Debugging; APIs; Databases; DSA; Interview Preparation; Projects.

## Required format for every topic
1. Definition and simple-English explanation.
2. Syntax and rules.
3. Why, where, when and when-not-to-use guidance.
4. Five complete runnable examples with question, code, output and explanation.
5. Five practice questions, each with complete solution code and explanation.
6. Five real-world use cases explaining where, when and how.
7. One complete runnable project with setup, sample output and tests.
8. Common mistakes, edge cases, interview Q&A, quiz and checklist.

Five use cases and one complete project are separate requirements. Do not substitute a project description for runnable code.

## Folder responsibilities
- days/: chronological day-by-day lessons and progress.
- core/: Python language reference and examples.
- exceptions/: exception handling and validation.
- files/: text files, paths, CSV, JSON and persistence.
- modules/: imports, packages and project layout.
- oop/: classes, objects and OOP projects.
- testing/: debugging, assertions and automated tests.
- apis/: HTTP, JSON APIs, requests, timeouts and error handling.
- databases/: Python database operations and parameterised SQL.
- dsa/: complexity, data structures, algorithms and patterns.
- interview/: question banks grouped by subject.
- projects/: complete end-to-end applications.

## Status definitions
- Not started: not taught yet.
- Ongoing: currently being taught/practised.
- Covered: taught/read, but independent practice is not verified.
- Completed: examples run, tasks attempted, project tested, quiz passed and learner can explain the topic.
- Next: next lesson to study.
